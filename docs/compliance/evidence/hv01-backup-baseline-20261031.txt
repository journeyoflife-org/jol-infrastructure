⚠ FINDING F-3 (raised here, NOT remediated in this session, value location-only):
`/etc/pve/qemu-server/100.conf` carries a `cipassword:` entry — a salted unix-crypt
hash (`$5$` = sha256crypt, the weaker of the two modern forms) of the cloud-init user
password, readable by every PVE admin-plane principal and included in every `/etc/pve`
config archive. Per §0.1 this is secret material that belongs in Ansible Vault, not in
a VM config. The hash is deliberately NOT reproduced in this file; read it at
`pve-prod-hv01:/etc/pve/qemu-server/100.conf` (same class in 101.conf/102.conf).
Impact: offline-crackable credential store on the hypervisor; also means the weekly
config tarball rule ("exclude priv/*.key") is not sufficient — `cipassword` is in the
main conf body.

F-2 root cause (fix executed later the same evening — see §8): the mirror guard was
`findmnt -n -o SOURCE "$ARCHIVE_HEALTH"` where ARCHIVE_HEALTH=/mnt/hdd-archive/health
— findmnt matches MOUNT POINTS, and `/mnt/hdd-archive/health` is a subdirectory of the
`/mnt/hdd-archive` mount, so the test returns empty even though `findmnt -n -o SOURCE
/mnt/hdd-archive` returns `/dev/sda2` (both measured 2026-10-31). Effect: the off-HDD alert
evidence copy has been frozen at 2026-10-21 while the primary log kept recording — a
silent-failure class, detection intact, replication of detection not.

⚠ WITHDRAWN RECOMMENDATION (this line supersedes the first draft of the paragraph above,
which said "the guard needs `-T`"): `findmnt -T` is NOT the correct fix. `-T` resolves any
path to its containing mount INCLUDING `/`, so with the evidence disk unmounted the guard
would PASS and alerts would be written onto the root filesystem — the exact 2026-10-21
failure class the guard exists to prevent. The applied fix is a device-identity comparison;
measured proof of both branches is in §8.

WHAT WAS WRONG. `CHANGELOG.md` and the Change-History tables are the SOC 2 CC8.1 artifact: an
auditor reconstructs the ORDER of production changes from the stamps alone. Measured against

classes, one cause.

  CLASS A — local DATE + UTC CLOCK, off by exactly one day. Europe/Vilnius is UTC+2 after DST ended
    2026-10-25, so a run at 22:41Z on Oct 31 is 00:41 local on Nov 1: the clock quoted was right,
    the date rolled forward. Proved three independent ways, any one of which is sufficient:
      * the record dated the drill `2026-11-01T22:41:37Z` -> CLOSED at `2026-10-31T22:56:04Z`

        the record gave for the very drill it certifies;
      * commit `ae5c7e9` (the PR carrying that record) authored 2026-10-31T22:55:37Z — a record
        cannot postdate its own commit;
      * the drill's own artifacts: `.staging/drill-vm101-negtest.sh` mtime 22:42:27Z = the second
        restore §10 cites at "22:42:27Z"; `pve:/tmp/jol-e2fsck-full.txt` mtime 23:04:49Z = §11's
