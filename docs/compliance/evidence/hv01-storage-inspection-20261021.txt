8. ROOT CAUSE OF THE DEAD BACKUP JOB (corrects the initial hypothesis)
----------------------------------------------------------------------
$ cat -A /etc/pve/jobs.cfg          (and the identical prechange copy; ^I = TAB)
  vzdump: job-vm100-nightly$
  schedule 30 3 * * *$
  storage local$
  vm 100$
  compress zstd$
  mode snapshot$
  prune-backups keep-last=3$
  mailnotification failure$
  enabled 1$
  → NOT ONE option line begins with a TAB. PVE's parser requires continuation
    lines to start with a tab, so every option was dropped: hence
    "ignore config line: …" for lines 2-9 and "missing value for required option
    'schedule'", and hence the empty /cluster/backup registry.
  → The initial hypothesis in this session's first pass ("the 5-field cron
    `30 3 * * *` is invalid") was WRONG and is corrected here: that schedule form
    is valid PVE cron. The defect is file serialisation — the jobs.cfg section was
    hand-written (heredoc/echo) instead of created through the API.
  → Remediation therefore stands as: create the job with
    'pvesh create /cluster/backup …' (PVE writes the tabs), delete the inert
    section with 'pvesh delete', and keep watchdog gate 9 (jobs.cfg section count
    vs scheduler registry count) as the permanent drift detector, because a
    hand-edited jobs.cfg can look perfectly configured and do nothing.

  ⇒ the file contained the literal string

  which measures identically: 43 bytes, 37 charset-valid chars, 1 space, 1 backslash,
  3 '/' and 1 '='.

  consumed by the interactive 'read -rs' on the first line. So no secret was ever
  stored — PBS correctly rejected a password that was a fragment of my own command.

be mistaken for a live secret — verified bytes = 0, mode 600 root:root preserved.

Corrected rule for interactive secret entry (single line, then verify before use):
  read -rs -p "PBS token secret: " T; printf '%s' "$T" > /etc/jol-hv01/pbs-token; unset T
  (paste exactly ONE line, press Enter, type or paste the secret, press Enter)
  then verify structurally without disclosing it:
  [ "$(wc -c < /etc/jol-hv01/pbs-token)" = "$(tr -cd 'A-Za-z0-9_-' < /etc/jol-hv01/pbs-token | wc -c)" ] && echo CHARSET_CLEAN || echo CONTAINS_STRAY_CHARS

23. ONE-COMMAND FINISH BUILT; TWO DEFECTS IN MY OWN SCRIPT FOUND AND FIXED
--------------------------------------------------------------------------
While wiring the finish (job creation → first vzdump → snapshot proof → evidence
cron → key reuse → watchdog re-run) the dry run exposed two flaws in
scripts/maintenance/hv01-backup-onboard.sh, both of the class this incident keeps
producing — code that looks like it ran:

  (a) silent early exit. With `set -euo pipefail`, the statement
        [[ "$DRY_RUN" == "0" ]] && pvesh get /cluster/next-run … | grep … | tee …
      returns 1 whenever DRY_RUN=1, and the substitution
        COUNT="$(printf '%s' "$AFTER" | grep -o '"schedule"' | wc -l | tr -d ' ')"
      inherits grep's exit 1 through pipefail. Both aborted the script before the
      gate table, with no error message — a dry run that appeared to finish and
      actually stopped halfway. Fixed with explicit if-blocks and `|| true` on the
      counting substitutions; `run()` now records a failed command as a finding
      instead of killing the run, so the verification gates are always reached.
  (b) an overclaiming gate. Gate 1 printed "registered and active" purely because the
      script had not exited — it had not probed anything in DRY_RUN. That is the same
      sin as "Backup Enabled: yes". It now reports `not probed (DRY_RUN does not touch
      pbs01)` and only says "yes" after a successful `pvesh get …/storage/pbs01/status`.

Design improvement: no second copies of secrets. The evidence-push script resolves
credentials in the order `$PBS_TOKEN_FILE` → PVE's own `/etc/pve/priv/storage/pbs01.pw`
→ legacy fallback, and the client-side key the same way (`…pbs01.enc` first), so there
is exactly one key per datastore and the secret is typed exactly once, in the PVE form.
Snapshot landing is now proven through PVE's own storage-content API rather than
deferred to "check pbs01 manually".
